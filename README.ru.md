# agentkeeper

![MIT](https://img.shields.io/badge/license-MIT-blue.svg) ![Go](https://img.shields.io/badge/Go-1.24-00ADD8?logo=go&logoColor=white)

**SSH-бастион для AI-агентов.** Дайте агенту *тикет*, а не ключи от продакшена.
Все сессии записываются. Каждая разрушительная команда получает секунду на размышление. Ноль установки на клиенте.

![demo](demo/agentkeeper-demo.gif)

Создан для автономных клиентов — LLM-агентов, CI-пайплайнов, деплой-ботов: обычный `ssh`, никаких интерактивных запросов (OTP передаётся прямо в имени пользователя), rsync / scp / sftp работают как есть. Бастион завершает входящее соединение и подключается к цели заново — поэтому середина поддаётся аудиту и записи.

## Зачем

AI-агенты переходят от написания кода к управлению инфраструктурой. Привычный ход — положить приватный SSH-ключ в песочницу агента / секреты CI / контекстное окно — ломается в трёх местах:

- **Ключ утекает.** Агент, читающий `~/.ssh/id_ed25519`, рано или поздно допустит утечку; песочницы и контекстные окна — не сейфы.
- **Ничего не записано.** Агент ночью перезапустил сервис — где доказательства?
- **До `rm -rf` — одна галлюцинация.** Автономному циклу не помешает «лежачий полицейский» перед необратимыми командами.

agentkeeper — те самые маленькие ворота, решающие все три проблемы:

- приватные ключи остаются **на бастионе** — у агента лишь отзываемый тикет;
- каждая сессия **записывается целиком** (asciinema cast + сырые байты + таймлайн команд);
- разрушительные команды получают **предупреждение «подумай ещё раз»**, попадающее прямо в контекст агента — LLM читает его и решает заново; чтобы подтвердить — отправьте ту же команду ещё раз.

## Возможности

- **Ноль установки на клиенте** — любой ssh-клиент: команды, интерактивный шелл, rsync / scp / sftp.
- **Никаких запросов, вообще** — OTP передаётся в имени пользователя (`<логин>+<цель>+<код>`); неинтерактивные агенты не зависают на вводе пароля — включая rsync и прочие неинтерактивные сценарии.
- **Идентичность = ключ + TOTP** — запись в `users` связывает публичный ключ тикета с его TOTP-секретом; имя пользователя не участвует в аутентификации.
- **Запись по умолчанию, fail-closed** — если запись невозможна, соединение отклоняется. Четыре артефакта на сессию + JSONL-индекс.
- **Серый список** — 50 правил RE2 из коробки: первое попадание — только предупреждение; та же команда, отправленная повторно (идентичный MD5), выполняется. Кавычки и бэкслеши удаляются перед сопоставлением.
- **Опциональный SOCKS5-выход** — бастион ходит наружу через прокси.
- **Один бинарник** — Go, статическая сборка, без cgo, один YAML. Работает на любой маленькой Linux-машине.

## Быстрый старт

```sh
# установка одной строкой (Linux, последний релиз → /usr/local/bin)
curl -fsSL https://raw.githubusercontent.com/zagfai/agentkeeper/main/install.sh | sh

# или сборка из исходников:
git clone https://github.com/zagfai/agentkeeper.git && cd agentkeeper
CGO_ENABLED=0 go build -trimpath -ldflags "-s -w" -o agentkeeper .

./agentkeeper gen-secret                                   # TOTP-секрет для агента
ssh-keygen -t ed25519 -N '' -f ticket -C my-agent      # тикет агента
ssh-keygen -t ed25519 -N '' -f host_ed25519 -C agentkeeper-host

cp agentkeeper.example.yaml agentkeeper.yaml      # впишите ключ тикета, секрет, default_key
./agentkeeper check -c agentkeeper.yaml
./agentkeeper -c agentkeeper.yaml                 # или systemd — см. agentkeeper.service
```

## Как подключается агент

```sh
# командный режим — то, что реально выполняет цикл агента
ssh -p2222 -i ticket 'deploy+10.0.0.5+123456'@<бастион> 'systemctl status nginx'

# разрушительная: в первый раз — только предупреждение (агент его прочитает)
ssh -p2222 -i ticket 'deploy+10.0.0.5+123456'@<бастион> 'rm -rf /var/lib/app'
# [graylist] This command may be destructive (matched rule: ...). Think it over.
# To proceed anyway, resend the exact same command.

# файлы — тот же синтаксис
rsync -a -e 'ssh -p2222 -i ticket' ./dist/ 'deploy+10.0.0.5+123456'@<бастион>:/srv/app/
```

Привязка аутентификатора: `./agentkeeper totp-uri -c agentkeeper.yaml` (otpauth-URI по каждой записи).

## Конфигурация

См. [`agentkeeper.example.yaml`](agentkeeper.example.yaml) — с полными комментариями. Главное:

- `users[]` — единственная таблица идентичностей: имя + публичный ключ тикета + TOTP-секрет;
- `default_key` — ключ бастиона к продакшену (никогда его не покидает);
- `proxy` — опциональный выход `socks5://…`;
- `gray.patterns` — правила опасных команд (RE2).

## Аудит

`recordings/<дата>/` на каждую сессию: `*.cast` (asciinema v2, воспроизводится), `*.in.raw` (0600), `*.cmd.log` (таймлайн), `*.meta.json`; плюс `recordings/sessions.jsonl`.

## Тесты

```sh
bash test/matrix/runall.sh    # 9 наборов, ~119 проверок, ~10 минут
```

## Безопасность

- Приватные ключи продакшена — только на бастионе; утечка тикета ≠ доступ к продакшену (нужен TOTP).
- Закрепите отпечаток host key бастиона на клиентах.
- Серый список — «лежачий полицейский», не граница безопасности; истина — в записях.
